# API

Endpoints are documented here as they're built, one row per route. Every
error response uses the uniform shape `{"detail": "...", "code": "..."}`.

| Method | Path | Role(s) | Request | Response |
|--------|------|---------|---------|----------|
| GET | /api/health | public | — | `{status}` |
| GET | /api/public/config | public | — | `{needs_setup, institution_name, current_term, student_signup_enabled}` |
| GET | /api/public/departments | public | — | `[{id,code,name}]` (e.g. for staff onboarding / admin UIs) |

| PATCH | /api/admin/departments/{id} | admin | `{hod_id}` (nullable) | `DepartmentOut`. Promoting a user makes their role `hod` (notified); demoting the previous head makes them a `teacher` (notified). |

| POST | /api/classes | teacher | `{name, code, content_library?}` | `ClassOut`, 201. 409 `CONFLICT` on duplicate code. | DELETE | /api/classes/{id}/students/{student_id} | teacher (owner) | — | 204. 403 if the caller doesn't own the class. 404 if the student isn't enrolled. Notifies the removed student. |

| POST | /api/exams/{id}/questions | teacher (owner) | `{type}` | `{exam: ExamOut, warnings[]}`, 201. Appends one newly generated question of `type`. 400 unless `draft`/`returned`, at 40 questions already, or if the AI couldn't produce a valid question. 502 `LLM_FAILED` on provider failure. |
| POST | /api/exams/{id}/attempts | student (enrolled) | — | `AttemptOut` + `{deadline, server_now}` (ISO datetimes), 201. 400 if the exam isn't `published` or the student already has a `submitted` attempt. 403 if not enrolled. | POST | /api/materials/{id}/ask | student (enrolled in the material's class) | `{question}` | `{answer, sources: [{page, heading}]}`. Retrieves the top 3 chunks by a plain-Python BM25-style keyword score (no vector DB), then makes one LLM call that must answer only from those chunks, in 2-5 sentences, citing page/heading, and say so if the chunks don't contain the answer. With `LLM_PROVIDER=mock`, returns the top chunk's first two sentences. Rate-limited to 20 calls/minute per user. 400 if the question is under 3 characters or the material has no chunks. 403 if not enrolled in the material's class. 404 if the material doesn't exist. 502 `LLM_FAILED` on provider failure. |

## Hardening

- **Rate limiting** (in-memory, per server process): `POST /api/auth/login` is limited to 10 requests/minute per client IP (`429 RATE_LIMITED`); `POST /api/exams/generate`, `POST /api/exams/{id}/questions/{qid}/regenerate` and `POST /api/materials/{id}/ask` are limited to 20 requests/minute per authenticated user.
- **Request size limit**: any request whose `Content-Length` exceeds `MAX_REQUEST_MB` (default 50 MB) is rejected with `413 PAYLOAD_TOO_LARGE` before its body is read. Material uploads additionally enforce the (admin-configurable) `max_upload_mb` setting on top of this.
- **Uniform error shape** everywhere, including a catch-all handler for any unexpected exception: `500 {"detail": "Something went wrong. Please try again.", "code": "SERVER_ERROR"}`. Stack traces are logged server-side only, never returned to the client.
- **Structured (JSON-line) logging** to stdout for every request (request id, method, path, status code, latency, decoded user id — never the bearer token itself) and every LLM call (provider, latency, token counts when the SDK reports them). Passwords, tokens, API keys and student answer text are never logged.
- **CORS** is restricted to the origins listed in `CORS_ORIGINS`.
